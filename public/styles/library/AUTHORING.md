# Authoring a style for the miwale Game Style Library

Every style lives in its own folder `public/styles/library/<id>/` and consists of
exactly three hand-written files. Everything else (catalog, `llms.txt`,
`llms-full.txt`) is generated by `node tools/build-styles.mjs`.

| File | Audience | Purpose |
| --- | --- | --- |
| `spec.json` | page + machines | Design tokens and structured facts. Rendered in the style window. |
| `STYLE.md` | AIs + humans | The full, detailed spec. The single document an AI needs to reproduce the look. |
| `starter.js` | AIs + humans | Dependency-free starter kit: palette + the core drawing techniques + a `draw()` preview scene. |

The reference implementation of each style is the full module in
`public/styles/js/styles/<id>.js` (Canvas 2D, written for the game
*Jack vs. the Turnip Ancestors*). Specs describe the style **generically** —
"the hero", "a small melee enemy", "a large brute" — and use the reference game
only as an example. An AI reading the spec is building a *different* game.

Language: **English** for everything.

---

## 1. `spec.json`

All keys are required unless marked optional. Keep strings plain text (no markdown).

```jsonc
{
  "id": "neon",                         // = folder name = id in the module
  "name": "Neon Midnight",              // English display name
  "originalName": "Neon Mitternacht",   // name in the module
  "family": "Vector · Neon",            // English, "Broad · Specific"
  "tags": ["synthwave", "glow", "line art", "dark"],     // 4–8 lowercase tags
  "summary": "Glowing neon vector lines on a black holographic floor.",  // ≤ 140 chars
  "description": "2–4 sentences: what it looks like, how it feels, what makes it distinctive.",
  "mood": ["electric", "nocturnal", "rave"],             // 3–5 adjectives
  "bestFor": ["arcade shooters", "rhythm games"],        // 3–5 genres/use cases
  "avoidFor": ["cozy farming sims"],                     // 2–4
  "difficulty": { "stars": 3, "why": "English translation of js/core/effort.js" },
  "technique": {
    "renderer": "Canvas 2D (procedural, no image assets)",
    "pixelArt": false,                   // or { "scale": 1 } – world units per art pixel, copy from module
    "resolution": "How sharp/low-res it renders (e.g. 'native resolution, sprites baked at 4 px/unit')",
    "summary": "1–2 sentences: the core trick that produces the look.",
    "linework": "Outline/line rules: colour, width in world units, caps/joins.",
    "shading": "How forms get volume (flat, cel bands, gradients, dithering...).",
    "lighting": "Light direction, glows, darkness, colored light.",
    "texture": "Surface texture/noise/grain, or 'none'."
  },
  "palette": [                           // 8–20 entries, the REAL hex values from the module
    { "name": "Void", "hex": "#05040d", "role": "Background / ground base (~60% of the screen)" }
  ],
  "paletteRules": ["Rules about how colours are combined, ratios, what never appears."],
  "typography": [                        // fonts from the module's `fonts` list + its `css`
    {
      "family": "Orbitron",
      "weights": [500, 700, 900],
      "role": "HUD numbers, titles",
      "source": "Google Fonts",
      "sample": "LEVEL 07",
      "css": "font: 900 22px/1 'Orbitron', sans-serif; letter-spacing: .12em; color: #6ff4ff;"
    }
  ],
  "background": {
    "summary": "What the ground/backdrop looks like and how it is produced.",
    "layers": ["Ordered list, bottom to top: base fill, texture, decals, overlays..."]
  },
  "characters": {
    "summary": "How characters are built (shapes, proportions, outline, faces, animation frames).",
    "rules": ["Silhouette/readability rules", "..."]
  },
  "effects": [                           // 4–8 entries
    { "name": "Hit spark", "how": "What it looks like and how it is drawn." }
  ],
  "ui": {
    "summary": "HUD look: panels, bars, borders, text treatment.",
    "css": "Copy-ready CSS for a HUD panel + bar in this style (derived from the module's `css`)."
  },
  "motion": ["Animation / timing rules: frame counts, bob, squash, flicker..."],
  "do": ["5–8 concrete rules"],
  "dont": ["5–8 concrete anti-patterns that break the look"],
  "performance": "Cost notes: what is baked once, what is per frame, known hot spots."
}
```

## 2. `STYLE.md`

Use **exactly** these `##` headings, in this order (the page and `llms-full.txt`
rely on them). Be concrete: real hex values, real sizes in world units
(the reference game shows 360 world units of height on screen; the hero is
~18 units wide and ~30 tall), real function names, real numbers from the module.
Target length 250–500 lines. This is the document an AI copies — make it
self-sufficient.

```markdown
# <Name> — Game Art Style Spec

> <summary>

<one paragraph description>

## At a glance
Markdown table: Family · Mood · Best for · Renderer · Pixel art · Difficulty (n/10) · Fonts · Key colours.

## When to use it
Bullets: good fits, bad fits, and why.

## Color palette
Table: Swatch name | Hex | Role. Then palette rules (ratios, contrast, forbidden colours).

## Typography
Each font: family, weights, role, Google Fonts URL, example CSS. Text effects (shadows, outlines, letter-spacing).

## Rendering technique
The pipeline in numbered steps: what is baked at init, what is drawn per frame, draw order, resolution/pixel rules.

## Background and ground
How the world floor/backdrop is made: textures, noise, decals, colours, scale.

## Characters
Construction of the hero: shapes, proportions, outline, face, colours, animation frames, facing.

## Enemies and props
How secondary actors and environment props are built so they stay readable and on-style.

## Effects and particles
Projectiles, hits, deaths, pickups, dash, level-up: look + implementation.

## Lighting, shadows and post-processing
Shadows under actors, glows, vignettes, overlays, colour grading.

## UI and HUD
Panels, bars, borders, fonts, icon style. Include a CSS block.

## Motion and animation
Timings, easing, frame counts, idle/walk/hit/death behaviour.

## Do and don't
Two bullet lists.

## Implementation recipe
Numbered, step-by-step instructions an AI can follow to build a NEW game in this style from scratch.

## Code
Short intro, then 2–5 fenced `js` blocks with the most important real techniques, cleaned up so they run
on their own (no `U.`/`G.` dependencies — inline small helpers). Point to `starter.js` and to the
full reference module `../../js/styles/<id>.js`.

## Adapting it to your game
How to re-theme without losing the look: what to keep fixed, what may change (palette swap rules,
new character types, other genres, other resolutions).

## Performance notes
Baking, caching, per-frame costs, budgets.

## Copy-paste prompt
A fenced `text` block: a ready prompt an AI user can paste ("Build my game <X> in the <Name> style: ...")
summarising the non-negotiable rules in ~15 lines.
```

## 3. `starter.js`

Plain ES2017 script, **no dependencies**, no network, no globals except the
registration at the end. 150–450 lines. It must faithfully demonstrate the
style's core technique (not a vague approximation) — port real drawing code
from the module and inline the few helpers it needs.

```js
/* <Name> — starter kit from the miwale Game Style Library (https://miwale.com/styles/).
   Dependency-free Canvas 2D. Free to copy and adapt. Full spec: STYLE.md */
(function (root) {
  'use strict';
  const PALETTE = { /* same hex values as spec.json */ };

  // ...technique helpers (documented with one-line comments)...

  /** Draws the hero with feet at (x, y). t = seconds, facing = 1 | -1. */
  function drawHero(ctx, x, y, t, facing) { /* ... */ }
  /** Draws a typical enemy with feet at (x, y). */
  function drawEnemy(ctx, x, y, t) { /* ... */ }

  /** Paints a complete preview scene into a w×h canvas at time t (seconds): ground, hero, enemies, an effect. */
  function draw(ctx, w, h, t) { /* ... */ }

  const Starter = { id: '<id>', name: '<Name>', palette: PALETTE, fonts: [/* Google Fonts families */], drawHero, drawEnemy, draw };
  root.StyleStarters = root.StyleStarters || {};
  root.StyleStarters['<id>'] = Starter;
  if (typeof module !== 'undefined' && module.exports) module.exports = Starter;
})(typeof window !== 'undefined' ? window : globalThis);
```

Rules for `draw(ctx, w, h, t)`:
- Must fill the whole canvas (no transparent areas) and work for any w×h (preview is ~960×540).
- Scale with `h` (e.g. `const s = h / 360;` and draw in 360-unit space).
- Animate with `t` (walk cycle, bob, flicker), deterministic for a given `t` — no `Math.random()` per frame
  (use a seeded hash). Must stay under ~8 ms per frame.
- Pixel-art styles: render into a small offscreen canvas and upscale with `imageSmoothingEnabled = false`.
- Text drawn on the canvas uses the style's fonts with a generic fallback.

## Checking your work

```bash
node tools/build-styles.mjs            # regenerate catalog + llms files
node tools/check-styles.mjs <id>       # schema, headings, starter runs, writes a preview PNG
```

`check-styles.mjs` prints the path of `starter-<id>.png`; open it and compare it
with `public/styles/shots/<id>.webp`. They should be recognisably the same style.
